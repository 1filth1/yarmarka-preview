# Yarmarka CRM — автономный backend (черновой этап)

Этот каталог — начало перехода от статического GitHub Pages preview к самостоятельному приложению на отдельном сервере.

## Архитектура

- FastAPI — HTTP API и серверная проверка прав.
- PostgreSQL 16 — единая база для всех клиентов и сотрудников.
- Docker Compose — запуск на мини-ПК/сервере.
- База не публикуется наружу; API привязан к localhost до настройки HTTPS reverse proxy.

## Уже заложено

- регистрация сотрудника со статусом `pending`;
- вход по логину и паролю (Argon2id через pwdlib);
- короткоживущий JWT;
- административный список ожидающих заявок, одобрение с назначением отдела и отклонение;
- заявки: администратор видит все, сотрудник — только назначенные ему;
- журнал ключевых действий;
- отдельная команда первичного создания администратора.

## Локальный запуск

1. Установить Docker Engine и Compose.
2. Скопировать `.env.example` в `.env`, заменить все секреты на случайные длинные значения.
3. Запустить `docker compose up --build -d`.
4. Создать первого администратора: `docker compose exec api python -m app.bootstrap_admin`.
5. Проверить `http://127.0.0.1:8000/api/health` и документацию API `http://127.0.0.1:8000/docs`.

## Важные ограничения текущего этапа

- GitHub Pages остаётся только статическим preview; он не запускает FastAPI или PostgreSQL.
- Этот backend пока не подключён к существующему HTML-интерфейсу.
- Сейчас схема создаётся через SQLAlchemy `create_all`; до первой рабочей установки нужно добавить Alembic migrations.
- Одобрение сотрудника пока выполняется администратором напрямую; одноразовые коды активации и отдельный экран управления пользователями ещё предстоит реализовать.
- Не выставляйте порт 8000 или PostgreSQL напрямую в интернет. Для внешнего доступа нужны HTTPS reverse proxy, firewall, rate limiting, secure cookies/токены и резервное копирование.
- Не использовать реальные клиентские данные до завершения аудита безопасности и тестов.
